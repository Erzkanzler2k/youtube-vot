# YouTube VoT — обход блокировок (ветка `bypass`)

Отдельная ветка для обхода блокировок РКН **без root** через встроенный
VPN-сервис Android (`VpnService`). В `main` этот код не попадает.

---

## Архитектура

```
VpnService (TUN-устройство) → BypassEngine (обработка пакетов) → "наружу"
                                         │
                                   Socket + protect()
                                   (сеть не "ходит" через VPN)
```

**Компоненты**

- `BypassVpnService.java` — `VpnService`:
  запрос разрешения у пользователя → `startForeground` (обязательно на API 26+)
  → поднятие TUN через `Builder` (адреса, маршруты, DNS) → передача
  файлового дескриптора движку.
- `BypassEngine.java` — движок обхода: читает пакеты из TUN, разбирает
  IPv4/TCP, применяет DPI-обход, исходящие соединения открывает через
  `Socket` с `protect()`. Сейчас это каркас.

**Ключевой предохранитель:** `BypassEngine.isAvailable()` всегда возвращает
`false`, пока движок не готов. Пока он `false`, сервис **не поднимает VPN** —
иначе недоработанный перехват просто отрубит интернет на устройстве.

---

## Статус

### Этап 1 — инфраструктура (готово, на устройстве не проверялось)

- [x] `BypassVpnService`: полный lifecycle (prepare → startForeground → establishTun)
- [x] Гейт `BypassEngine.isAvailable() == false` — VPN не поднимается, пока движок не готов
- [x] Регистрация сервиса в манифесте (`android.permission.BIND_VPN_SERVICE`)
- [x] Переключатель в настройках; запрос разрешения через
      `startActivityForResult(REQ_VPN_PERMISSION = 7001)`
- [x] Строки интерфейса bypass

### Этап 2 — движок DPI-обхода (не начат)

- [ ] Разбор IPv4-заголовка (`IHL`, `protocol = 6` TCP); в первом приближении —
      начальные сегменты потоков
- [ ] Выделение TCP-потоков по `(src, dst, ports)`, захват первого `ClientHello`
- [ ] Определение SNI из TLS-приветствия (расширение `server_name`) → домен
- [ ] DPI-эвейжн в стиле zapret: десинхронизация `ClientHello` для заблокированных
      доменов (out-of-order сегменты / лишние байты / избыточные заголовки),
      чтобы DPI провайдера не находил SNI в первых пакетах
- [ ] Исходящие соединения через `Socket(protect())` — трафик приложения идёт
      по VPN, выходящие сокеты не заворачиваются обратно в TUN
- [ ] `isAvailable()` станет `true` только когда движок готов **и** включен
      в настройках

### Этап 3 — проверка и полировка

- [ ] Тест на устройстве против реально заблокированных доменов
- [ ] Если обход не сработал — фолбэк: не ронять остальной трафик устройства
- [ ] Повторное подключение при смене сети, расход батареи, скорость

## Сборка

Ветку собирает тот же `build.ps1`, что и `main`. Приложение соберётся и без
этапа 2: VPN просто не включится (гейт `isAvailable()`).
