# Что нового в 2.2.1 (хотфикс после эмулятор-тестов)

Исправления по итогам полного прогона на виртуальном устройстве (Android 14, x86_64).
2.2.0 содержала три блокера, из-за которых обход физически не работал:

### 🐛 Исправлено
- **«Чёрная дыра» движка**: весь трафик приложения через TUN идёт с адреса самого
  TUN (10.9.0.2), а движок молча отбрасывал пакеты именно с этого адреса источника —
  браузер висел на «Нет соединения» (154 TX против 17 RX на tun0, ноль внешних
  соединений). Фильтр убран, добавлена наблюдаемость первых пакетов.
- **VPN не снимался**: в состоянии fg-сервиса `stopService()` и даже `stopSelf()` не
  доходили до останова — tun0 оставался висеть. Теперь в stop-команде TUN закрывается
  синхронно (`engine.shutdown()`), затем `stopSelf(startId)`; сервис гарантированно
  умирает, почтовый интерфейс исчезает.
- **Падение FGS на Android 14+**: `SecurityException: startForeground ... FOREGROUND_SERVICE`
  на API 34+/targetSdk 35 — добавлены permission `FOREGROUND_SERVICE` +
  `FOREGROUND_SERVICE_SPECIAL_USE`, тип `specialUse` и property для сервиса.
- **Апдейтер**: источник jsDelivr стал первым (не зависит от блокировки github.com в РФ),
  точная версия резолвится через свежий API `data.jsdelivr.com` (CDN-кэш `@latest` может
  держать старый контент до ~12 ч), APK скачивается с CDN-зеркала, добавлены таймауты
  (8 с / 7 с) и логирование (`YouTubeVotUpdate`).

### ✅ Проверено на эмуляторе
- YouTube Home без VPN и сквозь TUN (движок пишет ответы: RX растёт).
- VPN ON → OFF → ON → OFF: tun0 поднимается и снимается, сервис умирает.
- Проверка обновлений: jsDelivr отвечает первым, «установлена последняя версия» без
  сбоев.
