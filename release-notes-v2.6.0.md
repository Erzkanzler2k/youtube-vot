# Что нового в 2.6.0

Обход DPI-blockировок теперь проверяет сам себя и подбирает стратегию на устройстве.

### ✨ Добавлено
- Измерение обхода: приложение проверяет реальный проход трафика через десканк и показывает результат, а не нажатие кнопки.
- Автоподбор стратегии: быстрый замер, затем две дешёвые проверки, затем полный перебор каталога с остыванием.
- Проверка по четырём стабильным хостам YouTube (страница, API, изображения, видео-CDN): они душатся по-разному, поэтому проверка одного хоста давала ложный вердикт.
- При равных замерах побеждает наименее агрессивная стратегия — меньше расход батареи и риска.
- Стратегия меняется только при значимом выигрыше, чтобы выбор не метался между запусками.
- Отчёт о провале: перечень проверенных хостов, число перебранных стратегий и конкретные действия вместо молчаливого отказа.
- Настройка MTU туннеля (по умолчанию 1400).

### 🔧 Исправлено
- Индикатор обхода больше не показывает «работает» до фактической проверки.
- Выключен UDP: стратегии не рассинхронизируют QUIC, а YouTube в WebView сначала идёт именно по нему — из-за этого мог быть зелёный тест и чёрный экран.
- IPv6 заведён в туннель: раньше часть трафика шла мимо обхода.
- Приложение больше не перехватывает DNS всего телефона через 1.1.1.1 — недоступность этого резолвера ломала сеть у всех приложений.
- При провале обход выключается, а не продолжает гонять трафик телефона через себя.
- Сборка: ZipFix больше не даёт путь `lib/lib/<abi>/…`, и нативные библиотеки всегда соответствуют текущим исходникам (устаревший скомпилированный класс молча собирал APK вовсе без них).

### 📋 Проверено
- Сборка Java 8 проходит, APK выровнен, обе native-библиотеки входят во все четыре ABI.
- Логика вердиктов, медианы и порога значимости прогнана автоматическими проверками.
- Подпись APK постоянным release-ключом, v2/v3 — как в предыдущих релизах.

### ⚠️ Ограничение
Пороги замеров (5 с / 1.5 с / коэффициент 1.5) пока не откалиброваны: осмысленные значения требуют замеров в заблокированных сетях. Замер идёт из отдельного изолированного процесса приложения; что его трафик действительно проходит через туннель, нужно подтвердить на устройстве в заблокированной сети. Если у вас обход не заработал — напишите, какая сеть и оператор, это ускорит калибровку.
